## 2 模板 = 装饰层 + 信息层

一套白纸模板就是「一张图 + 一组颜色 + 一段文案」：

```js
{
  id: 'paper-milktea', series: 'paper', family: 'paper',
  ink: '#5b3a22', accent: '#b07a45',   // 文字与点缀色
  art: 'milktea',                       // packageTpl/art/milktea.webp
  copy: { title: '免费 Wi-Fi', sub: '扫码连接 · 无需询问' },
  vertical: '扫码连网',                  // 侧边竖排小字（可关）
  prints: ['a6', 'a5', 'a4'], shape: '1:1.4',
  scene: ['milktea', 'cafe'], mood: ['温馨', '都市'], region: '极简'
}
```

信息层的排布不手填坐标，而是**从图里量**：`tools/art-bounds.js` 对装饰图做 8 邻域
连通域分析（阈值「任一通道 < 248 算有内容」，面积 < 0.00002 当噪点），得到

```
icon   顶部圆形徽章的外接矩形      信息层不许压
avoid  四角插画的外接矩形 ×4       文字与二维码都不许压
safe   被上面两者夹出来的中间区    信息层在这里排
```

量出来的结果是 0~1 的相对比例，与画布尺寸、打印规格无关，所以 A6/A5/A4 用的是同一份
坐标。换一张插画只要跑一次 `node tools/art-bounds.js`，不用重排。

信息层固定顺序：`免费 Wi-Fi` 标题 → `扫码连接 · 无需询问` 副标题 → 二维码（白底 +
4 模块静区 + 主题色圆角边框）→ 网络名（Wi-Fi 小图标）→ 密码（锁图标）→ 店名；侧边
竖排小字可关。小图标是主题色圆角方块 + 白色字形，跟着画布缩放。

放不下时自动缩（`MAX_ATTEMPTS = 4`），但守毫米下限：

```
标题 3.4mm · 副标题 2.1mm · 网络/密码行 2.3mm · 店名 2.6mm · 二维码 18mm · 单模块 0.4mm
```

缩到下限还放不下就返回 `warnings`，编辑页日志里能看到「已缩字 ×0.83」。

### 装饰图为什么和之前那批素材不一样

先把话说清楚，免得以为素材「换掉了」：

| | 仓库里现在的 6 张 | 之前提供的 `assets/ornaments/` |
| --- | --- | --- |
| 来源 | `tools/make-art.js` 程序生成 | Wikimedia 公有领域书籍花饰（fleuron / tailpiece） |
| 形态 | 1200×1680 **整层白底图**，主题徽章 + 四角插画，一套一张 | 最长边 256px 的**纯 alpha 剪影**，几十个零件 |
| 与场景的关系 | 每套对应一个场景（奶白/红汤/山宿/花漾/清谈/岁红） | 通用花边，与「奶茶」「火锅」无对应关系 |
| 排版 | `tools/art-bounds.js` 量出 `avoid` 区，文字自动避让 | 剪影没有版面信息，每套都得手工摆位、手工标避让 |
| 换色 | 按模板 `palette` 生成，改一行色值即可 | 需要逐张染色 |

结论：花饰**不是不好，是做不了「自动算避让 + 一图对一套场景」**。所以本期没有为了
花饰去重画素材，也没加新模板——素材层保持「程序生成整层」这条线，花饰留作以后做
「边角小饰」的素材库（届时按模板 palette 染色 + 手工标一次 avoid，不必重画整层）。

`docs/screens/phase1/art-compare.png` 是两者并排的实际编辑效果图，右侧那张特意让花饰压到
店名上，标出「没有避让坐标会怎样」。

## 3 打印

### 几何

尺寸全在毫米里算，渲染时才乘「每毫米多少像素」：预览是屏幕像素，导出是 11.81 px/mm
（300dpi）。所以预览与成品是同一版式，不会「预览对、打印错」。

网格是解出来的，不是写死的：

1. 纸边让出外边距（常规 8mm / 窄边距 4mm）；
2. 每格四周再让 2mm 裁切间隙；
3. 格子里按**模板自己的比例**拟合一张牌并居中——比例是硬约束，边距不能把它拉变形
   （1:1.4 的牌放横版纸会变「矮胖」；`ember` 是 2:1、`still-water` 是 1:1，
   早期版本一律按 1:1.4 排，它们就被拉变形了）；
4. 每次拟合都试正放与旋转 90°，**只有正放不达标（码或模块跌破下限）才旋转**，
   避免整版内容莫名躺倒；
5. 允许网格空一格：8 份用 3×3 而不是 2×4。

A4（边距 8mm、`山宿` 1:1.4、29 模块）实测：

| 版式 | 竖版 A4 每份 | 码 / 单模块 | 横版 A4 每份 | 码 / 单模块 |
| --- | --- | --- | --- | --- |
| 整张 1 份 | 190×266mm | 87.6mm / 2.37mm | 136×190mm | 62.4mm / 1.69mm |
| 半张 2 份 | 98×137mm | 44.9mm / 1.21mm | 136×190mm | 62.4mm / 1.69mm |
| 卡片 4 份 | 93×130mm | 42.9mm / 1.16mm | 66×93mm | 30.5mm / 0.82mm |
| 迷你 8 份 | 61×85mm | 28.0mm / 0.76mm | 66×93mm | 30.4mm / 0.82mm |

迷你原来是 2×4、每份 47×66mm，副标题只有 1.40mm、码 21.7mm。改成 3×3 空一格后每份
面积大 86%，副标题回到 1.79mm，码 28.0mm。剩下的小字警示（1.79 < 2.1）仍然照实提示。

横版的「整张」和「半张」每份一样大（一张 1:1.4 的牌放在横版纸上一行只放得下一张），
所以横版更适合半张与卡片，界面上照实显示，不藏。

### 导出

离屏 canvas 按 A4 300dpi 出图（2480×3508），失败降 200dpi（1654×2339）再试一次；
出图后 `wx.saveImageToPhotosAlbum` 存相册，或 `wx.showShareImageMenu` 直接发给打印店。
导出成功会往 `wifi_works` 记一条作品。

导出走的是 `utils/sheet-render.js`，它按 `draw.drawTemplate` 分派到白纸 / 深色各自的渲染器，
**模板的底色、装饰、色板、比例全部沿用编辑页那一套**。早期版本这里只调了 `paperRender`，
于是深色模板被印成了白纸。

### 门槛（按真实载荷算，不写死模块数）

模块数来自真实编码器（`utils/qr-metrics.js` 调 `createQR(payload).getModuleCount()`），
不是固定 33。同一句话换个密码，模块数就从 29 跳到 41/49，能印的版式也跟着变。

判定链：载荷 → 模块数 → 渲染器排版得出「码宽 / 卡宽」比 → 拼版算出码的毫米数 →
`单模块 = 码宽 / (模块数 + 8 静区)`。二维码 ≥ 15mm、单模块 ≥ 0.4mm 才 `usable: true`，
不达标这一档直接禁用，并写明「码 xx mm / 单模块 x.xx mm」。

实测：

| 载荷 | 模块数 | 迷你 8 份 单模块 | 结果 |
| --- | --- | --- | --- |
| 短（`Shiguang` / `coffee2024`） | 29 | 0.76mm | 四档全可用 |
| 长中文 SSID（14 字） | 41 | 0.55mm | 四档全可用 |
| 63 位长密码 | 41 | 0.55mm | 四档全可用 |
| 特殊字符（`!@#$%^&*()_+-=[]{}`） | 37 | 0.61mm | 四档全可用 |
| 界面允许的极限（32 字 SSID + 63 位密码） | 49 | 0.533mm | 四档全可用 |
| 合成超长（7000 字符级） | 81 | 0.244mm | 迷你禁用，其余可用 |

也就是说：**在界面能输入的范围内，四档都还能印**；真正被拦下来的是超出输入上限的载荷。
拦下来时点那一档会弹窗写明差多少，不会静默降级。

## 4 收藏 / 分享 / 隐私

- 首页卡片右上角 ♡，编辑页预览右上角 ♡，都写 `wifi_favorites`；首页右上角是「我的收藏」入口，只显示收藏过的模板。
- `onShareAppMessage` 只带模板 id（`/pages/editor/editor?tpl=xxx`），**不带 Wi-Fi 名称与密码**。
- 隐私说明（首页底部）现在是 7 段，把「本地处理」的边界讲清楚：
  1. 现在只在这台手机上处理；
  2. **但导出的图里带着密码**——存相册、发人、打印张贴，它就离开了这台手机；
  3. 密码不会被写进任何网络请求，可它会出现在你看得见、也可能被别人看见的地方；
  4. 以后若加云端同步，只同步店名/SSID/桌位号，且同步前弹窗征求同意，密码不参与；
  5. 相册权限：只在点「保存到相册」时申请写入，不读取相册、不用相机、不取位置；
  6. 本机草稿 / 作品记录可以一键清空，删除后不可恢复；
  7. 《用户隐私保护指引》可点开查看。
- 面板底部三行是**可操作**的，不是纯文字：`本机草稿`（已保存 · 清空）、`作品记录`（n 条 · 删除）、
  `用户隐私保护指引`（查看 ›）。删除走 `repo.removeDraft/clearWorks`，不靠清缓存。
- 相册授权走 `utils/privacy.js`：`wx.getPrivacySetting` → 需要授权则 `wx.requirePrivacyAuthorize`
  → 开发者工具里通常直接放行，真机且后台配好《指引》才会真弹。被系统权限拒绝才
  `wx.openSetting`；隐私授权失败是 errno 104/112，两条分支分开处理。
- 分享图片前会先弹一句「这张图上带着 Wi-Fi 密码」，确认再走 `wx.showShareImageMenu`。

离线（无需开发者工具）：

```bash
node tools/verify-qr.js         # 17 项：二维码编码与解码往返
node tools/verify-repo.js       # 38 项：数据层 API、预留字段、适配器、竖排开关、清空作品
```

一共 202 项，全过。

- `verify-paper` 的排版检查是几何求交：文字块与二维码框都不许碰 `avoid` / `icon`，元素之间也不许叠；
  对比度按 WCAG 相对亮度算，正文 ≥ 4.5（最低 3.18 是竖排辅助字，按大字标准 ≥ 3.0 判）；
  18 张（6 套 × A6/A5/A4）全部用系统 CIDetector 回读，与中文 SSID 载荷逐字符一致。

  （深色占比 60.2% vs 白纸 4.2%）；还比对「拼版估算的码尺寸」与「渲染回填的码尺寸」相差 < 10%。
- `verify-print` 的七组载荷专门压门槛：短、长中文 SSID、63 位长密码、特殊字符、空密码、无密码网络、超长。

## 6 已知限制

- **没上真机。** 本轮全部是模拟器验证。纸上扫不扫得出来、深色上墨会不会洇、相册授权弹窗、
  真机隐私弹窗、分享出去的样子，这五项必须真机再过一遍（清单见 `docs/screens/phase1/README.md`）。
- 装饰图是 webp（6 张共 80KB）。微信 `image` 组件 iOS 6.5.16+ / Android 6.5.1+ 支持 webp，
  canvas `createImage` 走同一套解码器；若某台老设备上装饰层空白，把 `utils/art.js` 的
  扩展名换成 `.png`、`tools/make-art.js` 改为输出 PNG 即可（体积约 500KB）。
- 首页「地区」这一维的取值其实是风格（新中式 / 日式 / 韩式 / 欧式 / 极简），6 套白纸
  都归「极简」。这是原有分类，本期没有改动，但标签名与取值对不上，下一期应改掉。
- 打印页读的是草稿（`wifi_draft`），所以必须先填过表单才有内容；空草稿会印出占位文字。
- 迷你 8 份即使改成 3×3，小字仍低于建议值（副标题 1.79mm / 网络行与密码行 2.10mm）。
  这是「一页塞 8 张」的物理上限，界面已提示，没有为了消警告去改字号。
- `showVertical` 现在跟着草稿与作品走；但**老版本存下的草稿没有这个字段**，读回来按「开」处理，
  与老版本的视觉一致，不会突然变样。
